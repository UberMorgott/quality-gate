# quality-gate

**Определяет стеки по наличию файлов-признаков и сам собирает из них проверки.** Это и есть то,
чего нет больше нигде: Task, just, mise, Mage, Make, pre-commit гоняют только то, что вы им
объявили руками; Nx автодетектит, но JS/TS-центричен и слаб по Go; Moon определяет тулчейны, но
задачи качества всё равно объявлять вам. Второе — **два уровня** (быстрый на каждый ход агента,
полный перед коммитом): нативно этого нет ни у кого, все эмулируют стадиями или отдельными
скриптами.

Wiring git-хуков не свой: его держит [Lefthook](https://lefthook.dev) (Go-бинарник, нативно на
Windows, без WSL). Наше — детект стеков и раннер. PowerShell 7+, Windows-first.

Метод, по итогам которого это собрано (946 замечаний -> 0, ~30 найденных реальных дефектов):
[PLAYBOOK.md](PLAYBOOK.md). README — про инструмент, PLAYBOOK — про то, зачем он такой.

## Установка

Одна команда на машину. Требует pwsh 7+ и git.

```powershell
irm https://raw.githubusercontent.com/UberMorgott/quality-gate/main/bootstrap.ps1 | iex
```

`bootstrap.ps1` клонирует (или обновляет) репозиторий в `%LOCALAPPDATA%\quality-gate`
(переопределяется через `$env:QUALITY_GATE_HOME` перед запуском), добавляет `<install>\bin` в
пользовательский PATH через реестр (исходный тип значения `REG_SZ`/`REG_EXPAND_SZ` сохраняется;
ведущие и двойные `;` не появляются). В GitHub Actions вместо реестра пишет в `$env:GITHUB_PATH`.
Предупреждает, если после установки `qgate` резолвится не в тот каталог, куда только что
поставили (PATH-шэдоуинг — второй чекаут раньше в PATH молча отвечал за все репозитории).

Уже запущенные терминалы и агенты сохраняют старый PATH — их нужно перезапустить.

После установки доступна единственная точка входа — `qgate` (через `bin\qgate.ps1` и
`bin\qgate.cmd` shim), абсолютный путь не нужен нигде.

## Запуск

```powershell
qgate                       # авто-детект изменённой стороны (быстрый уровень: только тронутые файлы)
qgate -All -Full            # все стеки, полный уровень
qgate -All -Fast            # все стеки, без сборки фронтенда
qgate -Only go              # только Go (значения: go web rust proto godot)
qgate -Only go,web          # несколько стеков (кавычки не нужны: -Only "go,web" и -Only go web -- то же)
qgate -Why                  # провенанс: какой файл-признак создал каждую фазу
qgate -All -Baseline HEAD~  # новые находки от ревизии (см. «Внедрение»)
qgate -Root C:\other\repo   # явный корень репозитория
qgate -All -Full -Quiet     # молчит на зелёном, печатает всё на красном
qgate -h                    # справка (также --help, -?, /?, help); exit 0
```

Все флаги (`-All`, `-Fast`, `-Full`, `-Only <stack[,stack]>`, `-Quiet`, `-Why`, `-Baseline <rev>`,
`-Root <path>`) передаются напрямую в `gate/check.ps1`. Аргумент, который не является ни одним из
них, — падение с указанием этого аргумента, а не молчаливая привязка к соседнему параметру.

`-Quiet` подавляет **только зелёный** прогон: при успехе не печатается ничего (ни `[PASS]`, ни
`[SKIP]`/`[WHY]`, ни `[INFO]` про устаревания), при провале — весь отчёт целиком. Код возврата
не меняется. Нужен там, где stdout уходит в контекст модели и за него платят: именно с ним
генерируется вызов в pre-commit-хуке (см. «Подключение репозитория»). В CI не ставится — там
строки `[PASS]` как раз и нужны.

Единственное, что `-Quiet` не глушит на зелёном, — `[WARN]` о **собственном конфиге гейта**
(`qgate.json`, `qgate.deferrals.json`), который не удалось прочитать. Это не признак пройденного
прогона, а сообщение о сломанном входе, и `-Quiet` — ровно тот режим, в котором гейт стоит на
коммите: раньше `qgate -All -Full -Quiet` на кривом `qgate.deferrals.json` печатал ноль символов.

`-Only` принимает список стеков через запятую: `-Only go`, `-Only go,web` (значения: `go`, `web`,
`rust`, `proto`, `godot`; `python` определяется, но не проверяется). PowerShell разбирает голое
`go,web` как **массив** и передаёт его двумя аргументами, поэтому имена стеков после `-Only`
читаются как его значение независимо от того, что шелл сделал с запятой: `-Only go,web`,
`-Only "go,web"` и `-Only go web` — одно и то же. Раньше документированный пример падал на самой
же документации: `-Only go,web` в pwsh упирался в `unexpected argument(s): web`, а сообщение об
ошибке предлагало в качестве лекарства ровно то написание, которое только что отвергло.
Слово, которое не является именем стека (`-Only go banana`) — падение
`[FAIL] unexpected argument(s): banana`: раньше оно позиционно уезжало в `-Baseline`, и прогон
падал с `[FAIL] baseline revision not found: banana`, то есть причиной про фичу, которой
пользователь не касался. Пустое значение (`-Only ''`) — тоже падение
(`[FAIL] -Only was given an empty value`), а не молчаливое расширение прогона на все стеки:
`if ($Only)` — проверка на истинность, а пустое значение в PowerShell читается как отсутствие
(PLAYBOOK §0.1).

Имя, которого в репозитории нет, — падение (`[FAIL] -Only <name> -- no such stack detected here`,
exit 1), а не предупреждение: `-Only godo` с опечаткой в CI или в lefthook раньше не проверял
ничего и выходил с кодом 0, то есть был зелёным пайплайном. Предупреждения в прошедшем прогоне
никто не читает. Это верно и в репозитории, где вообще нет ни одного стека: ранний
`[SKIP] no known stack found` стоял выше проверки `-Only` и отвечал за неё.

`-Only python` (стек определяется, но не реализован) — тоже падение, но уже не отдельным
правилом: под `-Only` этот стек и есть весь прогон, ни одна фаза не выполняется, и прогон валит
общий инвариант (см. «Fail closed»). В отчёте видно и то и другое:
`[SKIP] python (pyproject.toml) -- not implemented` и `[FAIL] no check phase ran`.

`-All` означает «все определённые стеки, игнорируя git status» — в том числе при выборе файлов
внутри стека. Фаза, которую гейт решил не запускать, никогда не выглядит как пройденная: она
печатает `[SKIP]`/`[WARN]` с причиной (`[SKIP] gdformat/gdlint -- no changed .gd files`,
`[WARN] no package-lock.json -- npm audit skipped`). Фазы, которой в проекте нет вовсе (нет
конфига линтера, нет build-скрипта), в отчёте нет — но стек, у которого так не выполнилось ни
одной фазы, помечается `[SKIP] <стек> (<признак>) -- no check phase applies here`, а не `[PASS]`.
Под `-All` рядом с настоящим стеком нереализованный остаётся пометкой и код возврата не меняет
(падение блокировало бы работу, которую гейт и не обещал проверять) — но если он в прогоне
единственный, проверено не было ничего, и прогон красный.

Без флагов смотрит `git status --porcelain=v1 -z` (NUL-разделитель, без экранирования — пути с
пробелами, табами и не-ASCII разбираются корректно; переименования учитываются; при вложенных
модулях владельцем файла считается самый длинный совпадающий путь): правки только внутри каталога
одного стека — гоняется только он; путь вне всех стеков (корневые файлы, CI, скрипты) — гоняются
все, и сказано почему: `[WHY] <path> belongs to no stack -- checking all of them`. Правка `.proto`
расширяет прогон отдельным правилом (`[WHY] proto changed`), потому что сгенерированный код живёт
в других стеках. Чистое дерево — `[SKIP] no changes`, exit 0. Каталог, который не является
git-репозиторием, не проходит молча: печатается
`[WARN] not a git repository -- checking every stack` и проверяется всё. Эти три случая (нет git,
нет правок, правки есть) различимы в выводе и не выдают себя друг за друга. На успехе — одна строка
на стек, на провале — сырой вывод, обрезанный до 6000 символов (и об обрезке сказано).

**Fail closed.** Падение самого гейта (недоступный корень, исключение в фазе) — это провал, а не
тихий проход. «Зелёный» — это прогон, в котором **выполнилась хотя бы одна фаза и все
выполненные отчитались успехом**. Прогон, не выполнивший ни одной фазы, зелёным не бывает:
`[FAIL] no check phase ran -- nothing was verified (<стеки>)`, exit 1. Инвариант один и стоит в
одном месте — считаются реально выполненные фазы, а не найденные стеки, потому что каждый
ложно-зелёный прогон приходил через свою дверь в одну и ту же комнату (нереализованный стек,
web-стек, у которого все фазы условны, `-Only` на стек, которого здесь нет).

Ровно два прогона законно не проверяют ничего — оба говорят об этом и выходят раньше инварианта:
`[SKIP] no changes` (чистое дерево на быстром уровне) и `[SKIP] no known stack found`
(в репозитории нет ни одного файла-признака и не задан `-Only`).

## Подключение репозитория

```powershell
qgate wire                    # текущий репозиторий
qgate wire -Target C:\repo    # другой репозиторий (-Root -- синоним, как у остальных команд)
qgate wire -NoHook            # без git-хука
qgate wire -CI                # с CI-воркфлоу (по умолчанию не создаётся)
```

Скрипты в целевой репозиторий **не копируются**. `qgate wire` записывает только конфигурацию:

- `*.go text eol=lf` в `.gitattributes` (дописывает сам, раньше только советовал);
- `.golangci.yml` рядом с каждым `go.mod`, у которого конфига нет (существующий не трогает).
  В шаблоне из scope линтера исключены `node_modules/` и `vendor/`: npm-пакеты возят внутри себя
  Go (`flatted`, который тянет за собой eslint, содержит реализацию на Go), `golangci-lint run
  ./...` из корня модуля заходит туда, и go+web-репозиторий краснел на чужом коде, который
  переписывает `npm i`. Для репозитория без конфига это не лечится — гейт на такой ровно и
  предупреждает `no .golangci.yml -- running golangci-lint on its defaults`. Фазы `gofmt`,
  `go build`/`vet`/`test` эти файлы по-прежнему видят: у go-тулчейна нет исключений по каталогам;

- `templates/eslint.config.js` и `templates/.stylelintrc.json` рядом с `package.json`, если своих
  нет (существующий не трогает — `kept existing eslint config`). Печатает строку установки:
  `npm i -D eslint @eslint/js typescript-eslint eslint-plugin-vue stylelint stylelint-config-standard-scss stylelint-config-recommended-vue`.
  Пакеты не поставлены — бинарь линтера отсутствует — фаза падает громко, молчаливого пропуска нет;
- `lefthook.yml` + `lefthook install`, если lefthook в PATH;
  иначе git-хуки `pre-commit` **и `pre-merge-commit`** из `templates/pre-commit` — тело одно
  и то же. Второе имя обязательно: merge, который коммитит сам (`git merge --no-ff`), гоняет
  `pre-merge-commit` и **никогда** `pre-commit`. Замерено на git 2.53 — при одном лишь
  `pre-commit` merge-коммит приземляется и не срабатывает ни один хук, так что две по
  отдельности чистые ветки сливаются в несобирающееся дерево, а отказ получает следующий
  обычный коммит, который в этом не виноват. `commit --amend` и `merge --squash` идут через
  `pre-commit` и покрыты. `cherry-pick` и `revert` не покрыты ничем: git даёт для них только
  `prepare-commit-msg` (он умеет отменять, но получает source `message` и на обычном коммите
  тоже, то есть гейт гонялся бы дважды на каждом коммите) и `post-commit`, который отменять не
  умеет. В worktree и подмодулях
  путь к хукам берётся у git (`git rev-parse --git-path hooks`). Если в репозитории уже лежит
  чужой `lefthook.yml` без задания quality-gate — громкое предупреждение с точными строками,
  которые надо вставить (строки цитируются из шаблона, а не набираются заново: однажды они уже
  разошлись, и вставлять предлагалось сломанный вариант). Шаблон:
  `run: 'if uname -o 2>/dev/null | grep -q Msys; then qgate.cmd -All -Full -Quiet; else qgate -All -Full -Quiet; fi'`
  — `.cmd` несущий: git и lefthook на Windows гоняют хук через Git-шелл, где PATHEXT не
  применяется и голый `qgate` даёт «command not found», exit 127 (в `bin/` лежат `qgate.cmd` и
  `qgate.ps1`, файла без расширения нет). Ненулевой pre-commit **отменяет коммит**, то есть это
  не пропущенный гейт, а репозиторий, где не проходит ни один коммит.
  Две проверенные ловушки в этой одной строке:
  1. **`command -v` пробу использовать нельзя.** Под `sh.exe` она возвращает ложь, хотя сама
     команда работает: `sh -c 'command -v qgate.cmd'` → rc=1, `sh -c 'qgate.cmd where'` → rc=0,
     `bash -c 'command -v qgate.cmd'` → rc=0. `lefthook run pre-commit` из шелла идёт через bash
     и проходит, настоящий `git commit` идёт через sh и падает.
  2. **lefthook срывает кавычки** из `run:` перед передачей в шелл: `case "$(uname -s)"` приезжает
     как `case $(uname` + `-s)`, а `grep -qE "MSYS|MINGW|CYGWIN"` теряет кавычки и `|` становится
     двумя пайпами. Поэтому в строке нет ни одной кавычки, и переключение идёт по `uname -o`
     (одно слово `Msys` и под `sh.exe`, и под `bash.exe`), а не по `uname -s`, значения которого
     в этих двух шеллах разные.
  `-Quiet` — потому что в агентском потоке коммит делается тул-коллом, и stdout хука возвращается
  в контекст модели, где за него платят: замер на трёхстековом монорепо — 342 символа `[PASS]`
  на каждый коммит, при правиле «коммит на каждое изменение». Подавляется **только зелёный**
  прогон, провал печатается целиком (замер: green 0 символов, red 142 с полным диагнозом).
  В CI `-Quiet` не ставится — там строки `[PASS]` как раз и нужны, поэтому это свойство
  генерируемых хуков, а не глобальный дефолт;
- `.claude/settings.json` — **мержится**, не заменяется — с Stop-хуком, вызывающим
  `qgate stop-hook`;
- маркированный блок `<!-- quality-gate --> ... <!-- /quality-gate -->` в начале `AGENTS.md` и
  `CLAUDE.md`, инструктирующий агентов (включая Codex/ChatGPT) запускать `qgate` перед
  завершением, сообщать о его отсутствии как о блокере и включать команду с результатом в ответ.
  Если гейт сам неправ (падает, обвиняет корректный код, пропускает стек) — не обходить, а
  завести issue: `qgate where` даёт путь и коммит для воспроизведения,
  `gh issue create --repo UberMorgott/quality-gate` (шаблон `.github/ISSUE_TEMPLATE/gate-bug.md`);
- `.github/workflows/quality-gate.yml` из `templates/ci.yml` — **только при `qgate wire -CI`**
  (по умолчанию не создаётся; раньше репозиторий, осознанно удаливший этот workflow, получал его
  обратно на следующем `wire`). windows-latest; определяет стеки по файлам-маркерам и ставит
  только нужное: `setup-go` + `golangci-lint` + `govulncheck` для Go, `setup-node` + `npm ci`
  для web, `dtolnay/rust-toolchain` с clippy и rustfmt для Rust; `continue-on-error` убран; гейт
  по-прежнему ставится по тегу `$QG_REF`, по умолчанию `v1`. Монорепо: `go-version-file` получает
  найденный путь (например `server/go.mod`) из шага определения стеков; `npm ci` запускается в
  каталоге найденного `package.json` через `working-directory`.

Идемпотентна: повторный запуск сообщает «kept existing» / «already wired» / «unchanged» и ничего
не меняет. Предупреждает, если `qgate` не в PATH.

## Прочие команды

```powershell
qgate run         # то же, что qgate без подкоманды; все флаги гейта работают
qgate update      # git pull --ff-only в каталоге установки
qgate selftest    # red-then-green самопроверка гейта
qgate where       # путь установки, коммит, resolved-путь, версии тулчейнов
qgate outdated    # отчёт об устаревших прямых зависимостях и тулчейнах
```

`qgate run` существует затем, чтобы вызов гейта нельзя было спутать с подкомандой: `qgate -All`
и `qgate run -All` — одно и то же.

`qgate where` отвечает на вопрос «что гейт видит прямо сейчас»: путь установки и коммит,
resolved-путь `qgate`, версии всех тулчейнов (`go`, `golangci-lint`, `govulncheck`, `node`, `npm`,
`cargo`, `lefthook`, `buf`, `gdformat`, `gdlint`) и отдельная строка про бинарь Godot
(`$env:GODOT_BIN`, иначе `godot` на PATH — печатается версия и полный путь). Отсутствующий
инструмент печатается как `-- not on PATH`, а не пропускается молча: `GODOT_BIN`, заданный в одном
терминале, невидим агентскому хуку, запущенному из редактора, и именно это надо уметь увидеть.

## Устаревшие зависимости

```powershell
qgate outdated
```

Отдельная команда, а не фаза: «устарело» — не дефект, а гейт, чей вердикт зависит от того, что
мир опубликовал сегодня (тот же коммит зелёный сегодня и красный завтра). Уязвимости — дефект,
поэтому проверяются фазой на `-Full` (см. ниже).

Что проверяет:
- **Go** — только прямые зависимости (`go list -m -u`; косвенные — дело того, кто их тянет);
- **npm** — `npm outdated --json`; требует `node_modules` (иначе `[SKIP] ... run npm ci`);
- **Rust** — `cargo` (проверка версии rust/cargo);
- **тулчейны** — go (`go.dev/VERSION?m=text`), golangci-lint (GitHub API `releases/latest`),
  rust/cargo.

Вывод: `[OUTDATED] go  ./ github.com/foo v1.2.3 -> v1.3.0`,
`[OUTDATED] npm ./ vue 3.5.0 -> 3.6.1`, `[OUTDATED] tool go 1.26.2 -> 1.27.0`; если всё
свежее — `[OK] every direct dependency and toolchain is current`.

Никогда не роняет прогон (exit 0 всегда) — в том числе офлайн, при rate limit GitHub API или
мусорном ответе реестра: `[UNKNOWN] could not check: ... -- offline, rate limited or the tool failed`.
Неполный результат не кэшируется. Кэш инвалидируется, если `go.mod`/`go.sum`/`package.json`/
`package-lock.json`/`Cargo.toml` изменились после его записи. Сетевые ответы кэшируются по
репозиторию на 24 часа в TEMP, поэтому pre-commit не платит за поход в реестр каждый раз; явный
`qgate outdated` кэш игнорирует.

### Отложенные обновления

Необязательный `qgate.deferrals.json` в корне репозитория:

```json
{"dependencies": [
  {"name": "vue", "until": "2026-11-01", "reason": "ждём совместимости библиотеки компонентов"}
]}
```

Пока `until` не наступил, обновление не попадает в находки и не считается в сводке — но в каждом
отчёте `qgate outdated` печатается строкой `[DEFERRED] vue until 2026-11-01 -- <причина>`. Это не
глушилка: решение остаётся видно, чтобы к нему можно было вернуться.

`until` обязателен, и в этом весь смысл. Отложка без срока — просто тишина, а причина, которую
потом никто не найдёт, — то, ради чего файл и заведён. Когда срок прошёл, находка возвращается в
отчёт, а сверху добавляется `[DEFERRAL EXPIRED] … was deferred until … -- <причина>`. Прогон
гейта отчёт не печатает: на `-Full` он добавляет счётчики — `[INFO] N dependency update(s)` и,
если срок прошёл, `[INFO] N deferral(s) … have expired`; сами строки `[DEFERRED]` видны только в
`qgate outdated`.

Запись без `name`, без `reason` или с датой не в формате `yyyy-MM-dd` — `[WARN]`, а не тихий
пропуск, и это предупреждение доходит до `-Full` **в том числе с `-Quiet`**, то есть до
pre-commit-хука: файл, который гейт не смог прочитать, не прячет ничего и не молчит там, где
гейт стоит на коммите. Имя сопоставляется с находкой по «имя + текущая версия + стрелка», поэтому
`vue` не глушит `vue-router`. Правка файла инвалидирует суточный кэш.

**Интеграция с гейтом:** при `-Full` и только если все фазы прошли, в конец отчёта добавляется
одна строка `[INFO] N dependency update(s) available -- run 'qgate outdated' for the list`.
Не блокирует, exit code не меняет. С `-Quiet` эта строка не печатается — в отличие от `[WARN]`
о нечитаемом `qgate.deferrals.json`, который печатается всегда.
Stop-хук агента работает на `-Fast` и этой строки не видит — сети на ход агента нет.

## Проверка уязвимостей

На `-Full` (перед коммитом и в CI, не на ход агента — база уязвимостей в сети):

- **Go** — `govulncheck ./...`. Нет `govulncheck` на PATH — `[WARN]` с командой установки.
- **npm** — `npm audit --audit-level=high`. Нет `package-lock.json` — `[WARN]`, аудит пропущен.

Отличие от «устарело»: уязвимость — дефект, поэтому падает.

### Устаревший бинарь инструмента после бампа тулчейна

`govulncheck` находит CVE в stdlib, вы поднимаете директиву `go` в `go.mod` — и ломаются
инструменты, которые об этом сказали. Собранные старым тулчейном, они падают, ни разу не назвав
причину: `golangci-lint` отказывается читать собственный конфиг
(`the Go language version (go1.26) used to build golangci-lint is lower than the targeted Go
version (1.27.1)`), а `govulncheck` печатает `package requires newer Go version` на **каждый файл
репозитория** плюс четыре ошибки разбора внутри самой stdlib — пятнадцать строк, обвиняющих ваш
код, когда факт ровно один: бинарь старше тулчейна.

Гейт сверяет это сам, **до** запуска фазы, и печатает вместо сырой ошибки:

```
[FAIL] golangci-lint was built with go1.26, this module targets go1.27 -- rebuild it: go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@latest
```

Сравнение по `major.minor` — это языковая версия Go и та же гранулярность, на которой сверяется сам
`golangci-lint`: бинарь на go1.27.0 против модуля с `go 1.27.1` штатен и не репортится. Нет
директивы `go` в `go.mod` или `--version` не разобрался — проверка молчит, фаза идёт как раньше.

`qgate where` печатает, чем собран каждый инструмент, — то же расхождение видно одной командой:

```
  golangci-lint has version 2.13.2 built with go1.27.1 ...
  govulncheck v1.7.0 built with go1.27.1
```

Число берётся из build info бинаря (`go version -m <exe>`), **не** из его собственного вывода
версии. `govulncheck -version` печатает строку `Go:` — это тулчейн, активный в **текущем каталоге**:
один и тот же бинарь показывает `go1.26.2` из обычного каталога и `go1.27.1` внутри модуля, чья
директива `go` подтягивает новый тулчейн через `GOTOOLCHAIN=auto`. Сверять модуль с этим числом —
сверять модуль с самим собой: проверка не сработала бы никогда.

## Пиннинг версий тулчейнов

Необязательный `qgate.json` в корне репозитория:

```json
{"tools": {"golangci-lint": "2.13.1", "go": "1.26.2", "godot": "4.7.1", "gdtoolkit": "4.5.0"}}
```

Гейт сверяет версии на PATH с указанными. На быстром уровне расхождение — `[WARN]`, на `-Full` —
**падение** (`[FAIL] … install the pinned version or update qgate.json`, exit 1). Причина: пин
существует ровно затем, чтобы прогон был воспроизводим, а предупреждение этого не даёт — прогон
проходит на другом компиляторе или линтере, чем объявил репозиторий, и о запиненной версии не
говорит ничего. Вывод линтера нестабилен даже между патч-версиями, так что зелёный `-Full` на
2.13.2 ничего не сообщает про CI, который пинит 2.13.1. Правило то же, что у отсутствующих
`golangci-lint` и gdtoolkit: предупреждение на быстром уровне, падение на полном. Гейт по-прежнему
ничего не устанавливает — чинится либо установкой запиненной версии, либо правкой `qgate.json`, и
сообщение называет оба варианта.

Понимаемые ключи: `go`, `golangci-lint`, `cargo`, `node`, `buf`, `godot`,
`gdformat`/`gdlint`/`gdtoolkit` (одно и то же — обе утилиты приходят из одного pip-пакета одной
версии, любое из трёх имён пинит обе). Для Godot это важнее, чем для Go: набор правил `gdlint`
меняется между релизами gdtoolkit, а формат ошибок `godot --headless` — между минорными 4.x,
поэтому зелёный прогон на другом Godot, чем в CI, не предсказывает ничего.

Неизвестный ключ больше не игнорируется молча (`{"tools": {"typo": "1.0"}}` читался как
enforcement, а не делал ничего) — печатается `[WARN] qgate.json pins unknown tool '<name>'`.

## Определение стеков

По факту наличия файла-признака, а не по конфигу. Признака нет — стека нет — ноль затрат,
молча. Признак есть, а инструмента/конфига нет — сказано один раз, прогон продолжается.

| Стек | Признак | Статус |
|------|---------|--------|
| go | `go.mod` | реализован |
| web | `package.json` + `vite/next/webpack/rollup.config.*` | реализован |
| godot | `project.godot` | реализован |
| proto | `buf.yaml` | реализован |
| python | `pyproject.toml` / `requirements.txt` | **не реализован**, помечается `[SKIP]` |
| rust | `Cargo.toml` | реализован |

Нереализованный стек (python) печатает `[SKIP] ... not implemented` и не влияет на код возврата,
**пока в прогоне отработал хотя бы один настоящий стек**. Если он в прогоне единственный
(`-Only python`, или `-All` в репозитории, где кроме `pyproject.toml` ничего нет), не проверено
ничего — и прогон красный (см. «Fail closed»).
`Cargo.toml` без секции `[package]` (член workspace) пропускается — его покрывает корень
workspace. Нет `cargo` на PATH — стек падает (непроверяемый стек не проходит молча), как с
`node_modules`. Фазы, которая молча проходит, здесь нет — это было бы хуже отсутствия проверки.

Не пройденный по другой причине стек **валит гейт**: фронтенд без `node_modules` не «пропускается»,
а падает с `run npm ci` — непроверяемое не считается зелёным.

## Фазы и порядок

Порядок — от дешёвого к дорогому и от «без этого остальное бессмысленно» к деталям. Первая
упавшая фаза останавливает остальные: отчёт линтера по несобирающемуся коду — это шум.

То же и между стеками: упавший стек останавливает следующие за ним, но **молча этого не делает** —
каждый неотработавший стек получает строку `[SKIP] web web/ (…) -- an earlier stack failed, not run`.
Иначе красный `go` делал результат `web` неотличимым от репозитория, в котором `web` вообще нет.

**go** (в каталоге `go.mod`):
1. `gofmt -l .` — выходит с 0, даже когда перечисляет файлы, поэтому фаза падает по «есть вывод».
   Требует LF в рабочем дереве: добавьте `*.go text eol=lf` в `.gitattributes`, иначе CRLF-чекаут
   объявляется неотформатированным (install об этом предупредит).
2. `go build -o <temp> ./...` — `-o` в temp (свой каталог на каждый модуль, ключ от пути; раньше
   все модули писали в один общий каталог и затирали друг друга), иначе `go build ./...` роняет
   бинарник каждого main-пакета в рабочее дерево.
3. `go vet ./...`
4. `golangci-lint run` без ограничения числа находок (обрезанный отчёт врёт про итог: чинишь
   показанные — появляются новые). На `-Full` отсутствие `golangci-lint` в PATH — **падение**
   (гейт, который на коммите молча теряет главный линтер, не гейт). На быстром уровне — `[WARN]`,
   прогон продолжается.
5. Тесты разведены по уровням. **Быстрый:** `go test -short -failfast ./...` — `-short` даёт
   репозиторию способ убрать медленные наборы за `testing.Short()`, кэш тестов сохраняется.
   **Полный:** `go test -count=1 -failfast -shuffle=on -timeout=10m ./...` (без кеша, с
   перемешиванием) плюс `go test -race -short ./...`. Race-детектору нужен cgo/gcc — без него
   предупреждение, не падение. `$env:CGO_ENABLED` гейт **читает и не переопределяет**: значение
   `0` (обычная настройка для статических сборок) означает, что cgo нет, и фаза `go test -race`
   пропускается с тем же `[WARN] no cgo toolchain (gcc) -- go test -race skipped`.

**web** (в каталоге `package.json`): `stylelint` -> `eslint` -> `type-check` -> `build`.
`tsconfig.json` есть, а `vue-tsc`/`tsc` не установлен — фаза падает (непроверяемое не зелёное).
Бинарники берутся из `node_modules\.bin` напрямую, мимо npm-обёртки. `qgate wire` кладёт
конфиги ESLint (flat, ESLint 10, typescript-eslint + pluginVue `flat/recommended`) и stylelint
(`stylelint-config-standard-scss` + `stylelint-config-recommended-vue/scss` последним — он ставит
`customSyntax` для `.vue`), если в проекте их нет; фаза без конфига и без бинаря падает громко.
**eslint** запускается **без** `--fix` намеренно: гейт обязан сообщать о проблемах, а не молча
переписывать файлы, которые правит другая сессия, и не делать диффы агента непредсказуемыми.

**rust** (в каталоге `Cargo.toml` с секцией `[package]`):
1. `cargo fmt --check`
2. `cargo clippy --all-targets --quiet -- -D warnings` — отдельной фазы `cargo build` нет
   намеренно: clippy компилирует, пока линтит.
3. `cargo test --quiet`

**proto** (в каталоге `buf.yaml`; нет `buf` на PATH — стек падает):
1. `buf lint`
2. `buf format --diff --exit-code`
3. (только `-Full`) `buf breaking --against` — база: merge-base с origin/main, иначе HEAD~1;
   нет базовой ревизии или в ней ещё нет .proto — предупреждение, не падение. На время этого
   вызова гейт **выставляет** `$env:GIT_LFS_SKIP_SMUDGE=1` и возвращает прежнее значение после:
   `buf` клонирует базовую ревизию, и клон гоняет LFS-smudge по каждому tracked-бинарнику без
   remote, откуда его тянуть. `.proto` LFS-объектами не бывают, так что для этого вызова smudge
   не нужен. Другие фазы переменную не трогают.
4. (только `-Full`) `buf generate` + проверка дрейфа сгенерированного кода относительно .proto;
   нет `buf.gen.yaml` — пропуск с предупреждением. Рабочее дерево возвращается в исходное
   состояние.

**godot** (в каталоге `project.godot`; бинарь из `$env:GODOT_BIN`, иначе `godot` на PATH; нет ни
того ни другого — на `-Full` падение с явным упоминанием `GODOT_BIN`, на быстром уровне
предупреждение: все фазы, которым нужен бинарь, всё равно только на `-Full`, и ронять каждый ход
агента из-за инструмента, который на этом уровне не вызывается, — не то же самое, что «непроверяемое
не равно чистому». Оба godot-тулчейна симметричны: предупреждение на быстром, падение на полном):
1. (быстрый) `gdformat --check` и `gdlint` по изменённым `.gd`; при `-All` и `-Full` — по всем
   `.gd` проекта (кроме `.godot/` и `addons/`). Нет `.gd` в выборке — `[SKIP] gdformat/gdlint`,
   а не тишина. Нет gdtoolkit: на `-Full` — падение (`pip install gdtoolkit`), как и для
   `golangci-lint`; на быстром уровне — предупреждение. Репозиторий, которому gdtoolkit не нужен,
   исключает стек через `-Only`.
2. (быстрый) сканер `res://` и `uid://` — ищет в `.tscn`, `.tres`, `.gd` ссылки, которые не
   резолвятся, и `uid://` без соответствия; сообщает `файл:строка`. Несовпадение регистра в
   `res://` считается ошибкой даже на Windows (Godot резолвит без учёта регистра на Windows,
   но с учётом на Linux — иначе ошибка всплывает только в Linux-CI).
3. (полный) `--import` дважды (первый проход создаёт `.godot/`, значим только второй).
4. (полный) каждый `*_headless_test.gd` через `--script`.
5. (полный) смоук `--quit-after 1`.

Ключевая ловушка Godot: ошибки пишутся в stdout, не в stderr, и код возврата 0 для целого
класса ошибок скриптов. Поэтому вывод сканируется на `SCRIPT ERROR` и `ERROR:` — кода
возврата недостаточно. Это самый частый источник ложно-зелёного Godot-CI.

**Кросс-стековый фан-аут:** изменение только в каталоге с `.proto` больше не сужает проверку
до proto. Сгенерированный код пересекает границы стеков — правка схемы ломает и Go-сервер,
и Godot-клиент. Печатается `[WHY] proto changed -- generated code crosses stacks` и
проверяются все стеки.

## Два уровня

| Уровень | Что | Когда | Замер |
|---------|-----|-------|-------|
| `-Fast` | всё, кроме сборки фронтенда | каждый ход агента (Stop-хук) | 11 с |
| `-Full` (по умолчанию) | всё | pre-commit, CI | 48 с |

Замеры с проекта, на котором это выросло (Go-бэкенд + Vue SPA): разница почти целиком —
`vite build`, 36 с из 48. Дорогая фаза ловит только класс ошибок сборки (разрешение модулей,
ассеты, конфиг плагинов), и pre-commit с CI её всё равно закрывают. **Замерьте свои фазы и
вынесите самую дорогую в полный уровень** — иначе гейт начнут отключать.

## Для агентов

Три механизма, два из них автоматические после `qgate wire`:

**Claude Code** — Stop-хук в `.claude/settings.json`. При провале `qgate` выходит с кодом 2 —
ход не завершается, stderr уходит модели как причина блокировки. Агент получает обрезанный вывод
и идёт чинить, а не отчитывается «готово». Guard — счётчик неудач: после 3 блокировок подряд
(на репозиторий, на сессию) хук сдаётся и пишет причину. Проходящий прогон сбрасывает счётчик.
Счётчики старше суток удаляются.

Быстрый уровень смотрит только на **незакоммиченное** (`git status` + `git diff HEAD`), поэтому
ход, который отредактировал и сразу закоммитил, оставлял хуку чистое дерево — и `[SKIP] no changes`
пропускал ход, а на всех следующих ходах коммит уже никогда не станет «незакоммиченным». А правило
проекта — коммитить сразу, как только изменение проверено, то есть это нормальный случай, а не
краевой. Поэтому хук помнит коммит, на котором гейт был зелёным (файл в TEMP, ключ — репозиторий):
если HEAD ушёл дальше, ход проверяется целиком (`-All`), а не никак. Метку двигает только зелёный
прогон — иначе упавший прогон освобождал бы себя от проверки на следующем ходу. Нет метки (свежий
TEMP, первый запуск, метка старше суток) — считается «HEAD ушёл»: неизвестность трактуется в
безопасную сторону, ценой одного лишнего быстрого прогона.

Граница: закоммиченное проверяется на **быстром** уровне. Дефект, который ловится только на
`-Full` (`go test -race`, `govulncheck`, godot import/headless/smoke), через коммит для хука
проедет — его закрывают pre-commit и CI. Ход агента не может платить за полный уровень: замеры на
трёхстековом монорепо — чистое дерево 1.0 с, новый коммит (`-All`) 3.3 с, полный уровень 30.6 с.

**Почему не через `ai:` в lefthook.** Lefthook умеет генерировать хуки агентов и делает это
аккуратно, но генерируемая `lefthook run <hook>` на провале выходит с **1**, а Claude блокирует
ход только на **2** (замерено на 2.1.12). Поэтому Stop остаётся на нашем скрипте; git-хуки —
на lefthook.

**Codex / ChatGPT** — хукового механизма у них нет. `qgate wire` вставляет маркированный блок
в `AGENTS.md` и `CLAUDE.md`, инструктирующий агента запускать `qgate` перед завершением,
сообщать об отсутствии `qgate` как о блокере и включать команду с результатом в ответ.

**Замеренная ловушка lefthook на Windows** (2.1.12, ср. issue #1256): job вида
`run: pwsh -NoProfile -Command "exit 1"` отчитывается как **успех** — код возврата теряется.
`pwsh -NoProfile -File <script>` пробрасывает его правильно, `cmd /c ...` — снова теряет.
В `lefthook.yml` звать гейт только через `-File`.

## Использование с другой машины

```powershell
# 1. Установить гейт (один раз на машину)
irm https://raw.githubusercontent.com/UberMorgott/quality-gate/main/bootstrap.ps1 | iex

# 2. Перезапустить терминал (чтобы PATH обновился)

# 3. Подключить репозиторий
cd C:\path\to\repo
qgate wire
```

После этого pre-commit хук, Stop-хук агента, инструкции в `AGENTS.md`/`CLAUDE.md` и CI-воркфлоу
настроены. `qgate update` обновляет гейт до последнего коммита.

## Внедрение на существующей базе с сотнями находок

Первый прогон на нелинтившемся репозитории вернёт сотни замечаний. Обычная реакция —
выключить шумные правила глобально, и они не включатся уже никогда.

**По умолчанию — baseline, а не список исключений.**

```powershell
qgate -All -Baseline HEAD~
```

`-Baseline <rev>`, который не резолвится, отсекается до запуска линтера:
`[FAIL] baseline revision not found: <rev>`.

Разворачивается в `golangci-lint run --new-from-rev <rev> --whole-files`: всё, что старше
ревизии, вне области; всё новое — строго, **включая новый дефект в ещё не почищенном пакете**.
`--whole-files` судит тронутый файл целиком, а не только изменённые строки. Проверено:
на одном и том же коде `-Baseline HEAD` даёт 0, без него — тот же errcheck и код 1.

Фронтенд: у ESLint есть свой baseline — `eslint --fix --suppress-all` создаёт
`eslint-suppressions.json` (коммитить), и дальше **лишнее подавление само становится ошибкой**:
«There are suppressions left that do not occur anymore», чистится `--prune-suppressions`.
Это ровно то, чего не хватает списку исключений: почищенная запись не может тихо сгнить в
конфиге. У golangci-lint такого отчёта нет — после чистки пакета перезапустите без исключения и
удаляйте строку тем же коммитом.

**Список исключений по пакетам — запасной вариант**, для инструментов без baseline или когда
бэклог хочется видеть в диффе. Он грубее и слабее: новое нарушение внутри ещё исключённого
пакета остаётся невидимым. Механизм очереди (подробно — в комментарии `templates/.golangci.yml`
и в PLAYBOOK S3):

- все линтеры включены на весь репозиторий;
- шумные (у нас `errcheck`, `noctx`, `gosec`, `contextcheck`, `forcetypeassert`) гасятся
  **поимённо по пакетам** в `linters.exclusions.rules`, регэксп привязан к файлам самого пакета
  (`^dir/[^/]+\.go$`), без подкаталогов — иначе чистка родителя снимает строгость с детей;
- пакет почищен — строка **удаляется**, строгость на нём навсегда, регрессия валит гейт;
- список только сокращается, он и есть бэклог и прогресс-бар; второго трекера не заводить;
- порядок — по убыванию находок, кроме пакетов с нулевым покрытием: им сначала
  характеризующие тесты.

Мусор, который нельзя починить (недоделанные одноразовые утилиты, gitignored-каталоги),
выводится из области линтера **явно** через `exclusions.paths` с записанной причиной — из
сборки не выводится.

## Опциональные фазы

Не подключены. Каждую сначала прогнать руками, посмотреть вывод — и только потом ставить в
**полный** уровень (pre-commit / CI), не в быстрый.

**Go:** Uber

одинаковый результат (правила межпакетные и выдают по одной находке за раз).
`govet nilness` уже включён в шаблоне. `govet shadow` **не включать**: 178 находок, почти все —
легитимный скоупинг `err`.

**Фронтенд:** [knip](https://knip.dev) (мёртвые файлы, экспорты, зависимости),

флаги TS `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.

а не добавка: если ставите их, ESLint из гейта убирается, иначе получите две правды.

## Самопроверка

```powershell
qgate selftest
```

Гоняет гейт по фикстурам в `testdata/` и проверяет, что он **падает** на настоящем нарушении и
**проходит** после починки (red-then-green применительно к самому инструменту): определение
стеков, провенанс (`-Why` называет и найденный признак, и отсутствующий), предупреждение о
недостающем `.golangci.yml` ровно один раз, ошибка `go vet`, ошибка `errcheck` (доказывает, что
фаза линтера живая, а не просто присутствует), fail-closed на нерабочем корне, фронтенд без
`node_modules`, который обязан упасть, rust red-then-green (три проверки), не-git каталог
проверяется а не пропускается, шаблон lefthook зовёт `qgate`, `wire` пишет правило
`.gitattributes`, три проверки агентского контракта через .cmd shim (exit code ровно 2,
причина на stderr, stdout чист), proto red-then-green, определение godot-стека, громкое падение
godot без бинаря, сканер `res://` на битой ссылке и на несовпадении регистра, висячий `uid://`,
`-All` линтит `.gd` даже когда git не видит правок в `.gd`, пропущенная фаза видна как `[SKIP]`,
`-Only` с неизвестным стеком роняет прогон (а с известным — по-прежнему гоняет его),
отсутствующий `GODOT_BIN` не роняет быстрый уровень, но роняет `-Full` и в обоих случаях назван
вслух, `qgate.json` с неизвестным ключом предупреждает, `qgate.json` пинит gdtoolkit, чистое
дерево отчитывается как «нет правок», а не как «не git-репозиторий», путь вне стеков называет
свою причину и не сваливает её на proto, настоящая правка `.proto` по-прежнему расширяет прогон,
правка tracked-файла сужается до своего стека, Stop-хук блокирует нарушение, закоммиченное
при чистом дереве, тело сгенерированного хука исполняется под `sh` (тем шеллом, которым его
запускает git), а настоящий `git commit` проходит на чистом дереве и отменяется при провале гейта,
расхождение пина роняет `-Full` но не быстрый уровень (а совпадающий пин не роняет ничего),
живая отложка прячет находку но остаётся видимой, истёкшая — возвращает находку и видна даже
из кэша, нечитаемый `qgate.deferrals.json` называет одну причину и не выдумывает вторую,
кривая запись в нём даёт `[WARN]` и на `-Full`, и на `-Full -Quiet` (а на чистом прогоне
`-Quiet` по-прежнему не печатает ничего), `-Only python` роняет прогон и называет причину,
которая применилась, `-All` над одним только нереализованным стеком роняет прогон как пустой,
но рядом с настоящим стеком — нет, web-стек, у которого все фазы условны, не может отчитаться
зелёным и не печатается как `[PASS]`, пустое значение `-Only` и лишний аргумент после него
отвергаются с причиной про сам аргумент (а не про `-Baseline` и не про расширение прогона),
список через запятую по-прежнему работает, `-Only` в репозитории без единого стека роняет
прогон (а тот же репозиторий без `-Only` по-прежнему тихо пропускается).
92 проверки (часть уходит в `[skip]`, когда нет `GODOT_BIN` или gdtoolkit; финальная строка
печатает фактическое число — `all checks passed (110/110)`). Временный каталог самопроверки уникален
на прогон (два параллельных прогона не удаляют фикстуры друг друга). Гейт, который никто не
видел красным, не считается работающим.

## CI

CI должен пинить **тег**, не main — один и тот же коммит может пройти сегодня и упасть завтра
иначе. `qgate wire` генерирует воркфлоу с `$QG_REF` (по умолчанию `v1`).
